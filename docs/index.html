Carbon’s LaserWeeder uses vision to identify crops and weeds before laser targeting. I tested one perception question: what happens when crop foliage covers a weed? The test is whether a crop-risk limit chosen on validation images survives unseen images and added overlap. The images and model below are independent of Carbon.

05 / WHAT I WOULD DO NEXT

A useful failure, with clear limits.

The demo catches a real evaluation issue: the validation threshold did not hold the crop-risk line on test images. A production decision would need representative Carbon field video and the actual target-selection pipeline.

Built

Grouped image split, trained segmenter, validation threshold, test audit, overlap stress test, TorchScript export, and this reproducible report.

Still needed

Field-specific images, natural overlap labels, lighting and crop slices, meristem targets, and measured actuation outcomes.

Method and provenance +

224 annotated tiles from 28 original photos. All eight adjacent tiles from each original stay in one split: 18 train, five validation, five test. ResNet-18 encoder with U-Net-style decoder, weighted cross entropy and Dice loss. Best epoch selected on validation mean plant IoU; threshold selected on validation crop risk. Test bootstrap resamples images.

—

Rice paddies differ from Carbon’s production fields. Crop overlays are synthetic. Crop pixels called weed are a vision-risk proxy, not crop damage.
